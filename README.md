# Agent OS 期货研究工作台

独立的中国期货基本面研究 Web 与 Go BFF，默认端口 **8098**，服务身份为 `futures`。业务用户通过研究入口调用已发布的 Agent，不需要接触 Skill、MCP、提示词或模型配置。

## 研究与服务边界

AI 负责收集、校验、分类、留存和客观变化反馈；预测、方向与交易决定由用户负责。资料按具体日历区间组织，实绩、计划和第三方预测分开。当前尚未完成全品种资料覆盖或真实研究质量验收。

BFF 只通过 HTTP 访问发布的期货 Agent 与本应用任务，不直接访问数据库，没有迁移命令，不提供管理工具或凭证转发。用户鉴权使用 `BUSINESS_TOKEN`（兼容独立的 `ADMIN_TOKEN` 回退），服务调用使用另一枚 `SERVICE_TOKEN`。本地开发模式仍检查 Host、Origin 和写请求标记；密钥不进入前端。

## 已有功能

- 发起研究、查看进度、结果和留存阅读记录。失败、取消或效果不明的任务即使没有报告，也能查看已经保存的资料；这不会触发重试或把任务改成完成。
- 完成、失败、取消或效果不明的任务可回看每次送检草稿、当时检查反馈及按当前检查器进行的原文回查。完成任务的草稿标为历史版本，不替代最终回答；其他草稿仍明确尚无最终回答。输入摘要、反馈摘要、操作及投影版本必须配对；历史空提示列表可兼容。需 Runtime 配置 `research-draft-v1` 投影，固定工具 `mcp_futures-research_check_research_draft_v2`、输入 `arguments.draft`、输出 `content[0].text`，不向业务端开放通用管理回执。未配置时明确提示，不宣称没有已保存资料。
- `source://document/<id>` 只打开本任务范围内实际留存的阅读回执，不用当前知识库或其他任务替代历史来源。
- 新任务固定分类日期 `as_of` 和 `futures-evidence-v1` 输出契约；分类日期不证明资料在历史当天已经公开。旧 Markdown 结果仍可阅读。
- 只读报告检查核对结构、日期、存量/流量/累计量/产能/比率/未履约承诺分类、计划与实绩、有限的同口径比较，以及与留存原文的逐字引文匹配。
- 导出保留原始模型结果、哈希、校验版本及来源标签。检查未通过不会改写历史结果或隐藏可定位的引文。
- 报数可保留来源性质、正文限制和日期依据；AI 摘要与未确认来源仅作为候选线索。未知统计期允许起止日期同时留空，推断日期明确标注，两者不参加自动时间分类或比较。来源性质由 Agent 标注，不能把标注本身当验证结果。
- 每个核心问题支持带事实引用的客观资料解读，区别观察、冲突与证据边界；解读保持待核，不因引用编号存在就宣称结论已验证。既有问题、报数、原文和缺口仍保留。
- 研究问题取消旧 20,000 字节限制，单任务详情与报告检查读取完整模型结果。传输容量与 Runtime 对齐为 32 MiB JSON 请求、16 MiB 任务正文、64 MiB 单任务响应；这不是模型 token 配额。超限或不完整回包明确失败，不把截断正文作为成功响应。模型原生窗口和输出能力由 Registry/Runtime 的固定 Agent 版本负责；历史 Agent 仍保留原执行协议。

`GET /api/tasks/{id}/report-check` 的结构检查限制为 96 KiB JSON、40 条事实、30 组比较、8 个问题；来源读取最多 48 次请求、256 KiB 正文、15 秒及每文档前 8 条回执。超限或不支持的表达标为待复核，原始长结果仍完整可读并保留全文哈希，不截断模型输出。规则不能替代通用语义验证、来源真实性验证或独立交叉核验。

## Agent 内的草稿检查工具

`POST /mcp/research` 提供只读 `check_research_draft_v2`：输入有界 JSON 草稿和 `as_of`，不接收任务 ID 或 URL，不请求外部服务、不写数据库。完整 MCP 返回限制为 5,900 UTF-8 字节，低于 Runtime 的 6,000 字节归档阈值；保留路径、问题代码、总数与截断标记。相同代码的解释完全一致时才合并解释，不同解释分别保留。

此接口仅接受本服务的 `SERVICE_TOKEN`。需在 Registry 单独保存凭证，在 Runtime/ToolHub 配置精确主机与端口白名单，完成发现、检查、启用，再绑定固定版本 Agent。启动服务不会自动完成这些管理操作。旧任务保持原绑定，最终网页检查仍使用该任务的真实阅读回执。

提交提示要求至多两次草稿检查，并逐字输出最后一次送检的草稿；这是 Agent 指令，尚不是执行器强制的最终稿一致性保证。未知日期、来源受限及资料解读进入 `source_review`，不能要求模型编造日期换取通过。草稿工具没有读取任务回执，也不证明来源真实。真实任务的报告质量仍未通过，见 [读取修复与研究记录](https://github.com/euler-gaozl/agent-os/blob/main/docs/research-read-acceptance-20261014.md)。

`futures-evidence-v1` 增加可选 `facts[].evidence` 和 `questions[].findings`，当前检查器标识为 `futures-report-check-v5`；新读者保留旧报告兼容。旧版 BFF 会将包含这些字段的新报告显示为未结构化原文，因此回退后仍能读到完整结果，但不能声称新字段 UI 也兼容。此次没有修改 Runtime 的任务、原结果或数据库格式。

v4 修正推断日期的时间检查：`period_basis=inferred` 保持来源待核，不再因推断年份晚于分类基准日而触发 `future_actual` 结构修订。引用、日期依据待核和禁止比较仍保留；明确日期的未来实绩和无效日历区间仍需修订。此为 Mac 合成夹具验证，未复现原 Windows 私有任务，也不代表真实研究质量已验收。历史送检反馈保留原检查器标识与内容。

v5 保留 `format` 问题代码，提供有界的格式修订提示：JSON 语法/未闭合位置采用从 1 起算的 UTF-8 字节、行和字节列；未知字段和类型错误定位到数组下标与字段路径，重复键、深度/大小、schema 和必需数组分别说明。诊断不回显字段值或整段输入，不自动修报告，不接受额外字段；修复一个阻断后重新检查，可能发现后续问题。现有 MCP 输入/输出结构与历史反馈不变。Mac 合成回归通过；后续一次真实供应商调用的合成资料任务在 4 次模型请求内完成，最终稿与最后送检草稿一致，格式和引用检查有改善，但库存变化解读仍不完整、研究质量尚未通过。该任务同时采用了新版研究方法，不能把改善单独归因于检查器；不代表原 Windows 私有任务或真实市场业务验收。

完成任务草稿的展示通过 React 静态渲染、TypeScript 和独立 Web 构建验证；状态变化会重新读取草稿，历史送检版本与当前检查器分别显示。真实浏览器中的状态切换、桌面及窄屏交互仍待验收。

## 构建与部署

需要 Go 1.27.2、Node 24.19.0、pnpm 11.25.0；固定 SDK rc.2 和 `vendor` 支持独立构建。

```powershell
$env:GOWORK='off'; $env:GOPROXY='off'
./scripts/Build.ps1
pnpm --dir web install --frozen-lockfile --ignore-scripts
pnpm --dir web test
pnpm --dir web run build
./scripts/Package-Web.ps1 -Destination <新的绝对路径>
./scripts/Test-RelocatedPackage.ps1 -Package <发布包路径>
```

使用仓库外的 [服务配置](deploy/service.example.json)，以 `--config` 启动；`FUTURES_WEB_DIR` 指向源码构建的 `web/dist` 或发布包的 `web`。健康检查读取 `AGENTOS_CONFIG`。先安装提供应用证据接口的 Runtime；旧 Runtime 只能显示报告并明确提示来源接口不可用。

BFF 和 Web 必须一起升级/回滚，保持相同 HTTP 契约。就绪检查不证明所有下游可用。Actions 日常关闭；独立模拟测试与实际安装、付费模型、研究质量分别验收。[历史实现细节](docs/history/service-notes-20261014.en.md) 保留原始记录。
